     Redesign popup/main UI (light QTranslate-classic look), add cursor loading,
     fix Ctrl+Alt+W replace

     Context

     Three problems reported:
     1. Popup (Ctrl+Q) and main window look wrong — the user wants them to look
     like classic QTranslate/eQTranslate (screenshots: compact title-bar popup
     with lang pair + provider name + star/mic/speaker icons, a provider-icon
     toolbar, and a full main-window translator form with two panels + language
     dropdowns + Translate button).
     2. No visible "loading" at the cursor when Ctrl+Q is pressed.
     3. Ctrl+Alt+W (replace) doesn't actually replace text.

     Investigation found the real causes, not just cosmetic gaps:

     - Popup window is visually broken, not just "wrong style".
     QuickTranslatePopup.tsx renders a modal pattern (position:fixed
     full-viewport dark backdrop + centered 400px card) designed for embedding
     inside a page. But it's loaded standalone inside a real OS window that is
     only 320×120px, transparent, borderless (commands/window.rs). Result: the
     dark backdrop paints inside a tiny window and the 400px card overflows it.
     popup.html's inline body style also sets an opaque #1a1a2e background,
     defeating the window's transparent(true) and painting a dark box behind the
     card. This is why "UI after translate" looks broken.
     - Both windows race on the same Tauri events. translationStore.ts's
     listen("quick-translate"/"replace-translate", ...) runs at module scope,
     and both index.html (main window) and popup.html (popup window) bundle this
     store. So both windows independently receive the event and both call the
     guarded Rust commands (get_selected_text, replace_with_translation) at the
     same time. They share one OperationGuard AtomicBool, so one call always
     loses with "Operation already in progress" (silently swallowed by
     console.error). This makes both Quick Translate and Replace flaky depending
     on timing.
     - Ctrl+Alt+W was silently downgraded to plain Alt+W. domain/settings.ts,
     settings.rs, and CLAUDE.md all specify Ctrl+Alt+W, but commit c0d964b
     changed the actual registration in lib.rs to Modifiers::ALT only (comment
     says "Alt+W hotkey"). Even so, the deeper bug is: the global hotkey fires
     while the modifier key(s) are still physically held down. do_replace() then
     simulates Ctrl+C on top of that. If Alt is still down, the OS sees
     Ctrl+Alt+C, which most apps don't treat as "Copy" — so the clipboard never
     changes, capture fails with "No text selected", and nothing gets pasted.
     (Ctrl+Q doesn't hit this because its only held modifier, Ctrl, is exactly
     what Ctrl+C needs.)
     - Popup window clamps to a hardcoded 1920×1080 screen size (show_popup),
     which is wrong on other resolutions — a pre-existing // TODO in the code,
     fixed opportunistically while touching this file.

     User's answers on scope (confirmed):
     - Clone the light, Windows-classic look from the screenshots (not the
     current dark/red theme) for both popup and main window.
     - Redesign the main window into a full translator form (source textarea,
     language selects + swap, Translate button, result panel, provider toolbar)
     — not just the popup.
     - Provider icon toolbar shows all ~9 icons like the screenshot; only the 4
     implemented providers (Google, Microsoft, DeepL, OpenAI) are clickable, the
     rest render disabled/grayed placeholders.

     "Loading follows the cursor" is interpreted as: the popup is shown anchored
     at the cursor position captured at hotkey-press time with a visible
     spinner while translating (classic QTranslate behavior) — not a tooltip
     that continuously tracks mouse movement afterward. Flagging this
     interpretation up front.

     Plan

     A. Fix Ctrl+Alt+W replace (root cause, not just the symptom)

     - src-tauri/src/lib.rs: change the replace shortcut back to
     Modifiers::CONTROL | Modifiers::ALT + Code::KeyW (matches
     domain/settings.ts/settings.rs defaults and CLAUDE.md). Update the comment
     and tray menu item label to "Replace (Ctrl+Alt+W)".
     - src-tauri/src/commands/input.rs (do_replace) and
     src-tauri/src/commands/selection.rs (capture_selected_text): before
     simulating Ctrl+C, force-release Alt/Shift/Meta via enigo
     (Direction::Release) so the OS key-state is clean regardless of what's
     still physically held, then proceed with the existing Ctrl+C simulation.
     This is the actual fix for "modifier bleeds into the copy simulation".

     B. Fix the cross-window event race

     - src/stores/translationStore.ts: only register the
     quick-translate/replace-translate Tauri listeners when running inside the
     popup window — guard with getCurrentWindow().label === "popup" (from
     @tauri-apps/api/window). This removes the duplicate concurrent invokes from
     the main window.
     - src/App.tsx: drop <QuickTranslatePopup /> (no longer needed once the main
     window becomes the full translator form below).

     C. Popup redesign — compact, light, sized to its real window

     Files: popup.html, src/components/QuickTranslatePopup.tsx,
     src/styles/popup.css, src-tauri/src/commands/window.rs.

     - popup.html: change body background from #1a1a2e to transparent (window is
     already transparent(true); stop fighting it).
     - commands/window.rs: bump the popup's fixed size (define as named
     constants used by both create_popup_window's inner_size and show_popup's
     clamping math, so they can't drift again) to fit a title bar + body +
     provider row, e.g. 380×170. Replace the hardcoded 1920×1080 screen size
     with the real monitor size via Tauri's monitor API
     (window.current_monitor()), falling back to 1920×1080 only if unavailable.
     - QuickTranslatePopup.tsx: replace the modal pattern with a plain root card
     that fills the window:
       - Title row: "{sourceLangName} to {targetLangName}

     unused) src/services/tts.ts.

     QTranslate feature parity: History, Dictionary, Options, OCR, Mouse Mode

     Context

     User wants the app to match QTranslate's real feature set (tray menu
     screenshot: Dictionary, Text recognition, History, Keyboard, Options, Mouse
     mode, Enable global hotkeys) instead of the current minimal
     Quick-Translate/Replace/History-stub app. Explicitly not decompiling the
     proprietary QTranslate.exe (closed-source, no public code, and
     reverse-engineering it to copy behavior would be a legal/IP problem) — this
     is a clean-room reimplementation based on observed UX from the screenshots
     only. "Keyboard" (on-screen virtual keyboard) is out of scope; user
     picked: Options/Settings + Mouse Mode, Dictionary UI, OCR Text Recognition,
     History upgrade (Mouse Mode explicitly "làm thật" — a real global mouse
     hook, not a stub).

     Exploration surfaced real, pre-existing gaps worth fixing alongside the new
     features:
     - historyService.addEntry() is never called anywhere — History has always
     been dead (nothing is ever recorded), despite HistoryEntry already storing
     provider/timestamp.
     - settingsStore's quickTranslate/replace language configs are basically
     inert — translationStore.ts (popup) and the replace hotkey use their own
     hardcoded "auto"/"vi" state, never read persisted settings. Hotkey strings
     in settings ("CmdOrCtrl+Q" etc.) are never read either — the real shortcuts
     are hardcoded in lib.rs.
     - TranslatorForm's provider picker calls setActiveProvider (in-memory) but
     never saveSettings() — provider choice isn't actually persisted.
     - The tray menu's "Quick Translate"/"Replace" items exist but have no
     handler (silent no-ops).
     - services/dictionary.ts is complete dead code (unused anywhere), and even
     its lookupWord never populates synonyms/antonyms despite the type declaring
     them.
     - No screen-capture or OCR code exists at all (no windows/xcap/image
     crate).

     Researched and decided: OCR via Windows.Media.Ocr (built into Windows 10+,
     zero bundled binaries/language data) called through the windows crate, with
     xcap for region screen capture — rejected leptess/Tesseract because it
     needs bundling tessdata + native DLLs, which conflicts with keeping the
     installer small. Both Options and Dictionary will be their own Tauri
     windows (matching real QTranslate's behavior, per user's choice), opened
     from the tray menu; Dictionary also gets its own hotkey (Ctrl+Shift+Q,
     matching QTranslate's own documented default).
